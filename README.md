# Модель работы кэш-памяти (C++20)

Модель работы кэш-памяти процессора с поддержкой политик **Write-Back** и **LRU**, реализованная в виде header-only библиотеки на стандарте C++20, с тестовым стендом для прогона трасс.

---

## Параметры модели

* **Размер кэша (`cache_size`)**(S): `1024` байт (1 KB) 
* **Размер блока (`block_size`)**(B): `64` байта 
* **Число наборов (`NUM_SETS`)**(N): 8
* **Ассоциативность (`associativity`)**(A): `2`-way Set Associative
* **Политика замещения (`replacement_policy`)**: `LRU` (Least Recently Used)
* **Политика записи (`write_policy`)**: `WRITE_BACK` (read, write allocate)

# Требования к параметрам:
**block_size** (B) , **NUM_SETS**(N)  - обязательно  должны быть степенями двойки  **$2^n$** . 
=> должно выполняться равенство:          $N = S / (B \times A) = 2^n$

# Гайд по использованию тестового стенда

### Формат входных данных (трассы)

Стенд считывает команды формата:

	Чтение: R <hex_адрес> <размер_байтов_dec>

    R 1000 4 — прочитать 4 байта по адресу 0x1000.

    Запись: W <hex_адрес> <байт1_hex> <байт2_hex> ...

    W 1000 DE AD BE EF — записать 4 байта 0xDE 0xAD 0xBE 0xEF по адресу 0x1000.

# !!! Важно по поводу входных данных
И чтение и запись не должны выходить из одного блока памяти
(offset + data_size <= block_size) 

# Запуск программы

1. Запуск с файлом трассы (вывод логов в консоль)
``` bash
./test_bench -t trace.txt
```

2. Запуск с сохранением трассировки в файл result.txt
```bash
./test_bench -t trace.txt 2> result.txt
```

3. Запус  заполнением вводом и выводом в командной строке 
``` bash 
./test_bench
```

* Вводные данные в виде пустой строки или начинающиеся с # не учитываются
